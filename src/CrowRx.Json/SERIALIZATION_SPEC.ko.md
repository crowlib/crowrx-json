# CrowRx.Json 직렬화 사양

상태: 초안
대상 버전: CrowRx.Json 2.x

이 문서는 [`SERIALIZATION_SPEC.md`](SERIALIZATION_SPEC.md)의 한국어판입니다. 두 문서는 동일한 사양을 설명하며, 한쪽의 계약을 변경하면 다른 문서도 함께 갱신해야 합니다.

## 1. 목적

CrowRx.Json은 범용 C# DTO를 위한 가벼운 JSON 직렬화 라이브러리다. 동일한 코어 라이브러리가 일반 .NET 환경과 Unity 환경에서 모두 동작해야 한다.

라이브러리는 다음 항목을 우선한다.

1. 정확하고 결정적인 결과
2. 작고 편리한 공개 API
3. 예측 가능한 성능과 메모리 할당
4. 조용한 데이터 손실 대신 명시적인 실패

임의의 런타임 객체 그래프를 직렬화하거나 `UnityEngine.Object` 인스턴스에 대한 Unity 직렬화를 대체하는 것은 목표가 아니다.

## 2. JSON 표준 준수

- 입력은 JSON 문법에 맞아야 한다.
- 파서는 뒤쪽 공백을 제외한 입력 전체를 소비해야 한다.
- 잘못된 입력은 실패해야 하며, 일부만 파싱한 값을 성공으로 반환해서는 안 된다.
- 객체 키는 JSON 문자열이어야 한다. 빈 문자열 키도 유효하다.
- `NaN`, 양의 무한대, 음의 무한대는 유효한 JSON 숫자가 아니다.
- 문자열 이스케이프, 유니코드 이스케이프 시퀀스 및 서로게이트 쌍을 검증해야 한다.
- 중복된 객체 키는 기본적으로 거부한다. 다른 정책은 향후 옵션으로 정의할 수 있다.

## 3. 지원하는 루트 값

다음 JSON 값은 문서의 루트에 올 수 있다.

- 객체
- 배열
- 문자열
- 숫자
- 불리언
- `null`

요청한 대상 타입이 `null`을 담을 수 있으면 루트 `null` 변환은 성공하고, 그렇지 않으면 실패한다.

## 4. 지원하는 C# 타입

### 4.1 기본 스칼라 타입

- `bool`
- `string`
- `char`
- 부호 있는 정수 타입과 부호 없는 정수 타입
- `float`, `double`, `decimal`
- 열거형
- 지원하는 값 타입의 nullable 형식
- `Guid`
- `DateTime`, `DateTimeOffset`

열거형은 기본적으로 이름을 문자열로 기록한다. 숫자로 표현된 열거형 입력은 명시적으로 활성화한 경우에만 허용한다.

`DateTime`과 `DateTimeOffset`은 문화권에 영향받지 않는 ISO 8601 표현을 사용한다.

숫자 변환은 범위를 검사해야 한다. 오버플로, 정밀도 측면에서 유효하지 않은 입력, 호환되지 않는 JSON 토큰 타입은 조용히 강제 변환하지 않고 실패한다.

### 4.2 컬렉션

초기 지원 컬렉션 타입은 다음과 같다.

- 1차원 배열
- `List<T>`
- 구체 구현을 설정하거나 커스텀 액티베이터로 제공한 `IList<T>` 할당 가능 타입
- `Dictionary<string, TValue>`
- 같은 생성 규칙을 만족하는 `IDictionary<string, TValue>` 할당 가능 타입

JSON 객체를 리스트로 암묵적으로 변환하지 않는다. JSON 배열도 딕셔너리로 암묵적으로 변환하지 않는다.

딕셔너리 키는 문자열이어야 한다. 문자열이 아닌 C# 딕셔너리 키를 사용하려면 명시적인 컨버터가 필요하다.

다차원 배열, 튜플, 집합, 큐, 스택 및 그 밖의 컬렉션 타입은 별도의 사양이 마련되기 전까지 지원하지 않는다.

### 4.3 DTO 타입

DTO는 5절의 규칙으로 직렬화 멤버를 선택하는 클래스 또는 구조체다. 인터페이스, 추상 클래스, 델리게이트, 포인터, 개방형 제네릭 타입은 명시적인 컨버터가 없는 한 지원하지 않는다.

다형성 타입 메타데이터는 기본적으로 출력하거나 입력받지 않는다.

## 5. 멤버 선택

### 5.1 기본 포함 멤버

CrowRx.Json은 기본적으로 다음 멤버를 포함한다.

- public 인스턴스 필드
- 직렬화할 때 public getter를 가진 public 인스턴스 프로퍼티
- 역직렬화할 때 public setter 또는 대응하는 생성자 매개변수를 가진 public 인스턴스 프로퍼티

static 멤버, 인덱서, 상수, 이벤트, 델리게이트는 항상 제외한다.

### 5.2 명시적인 포함과 제외

private 또는 protected 필드와 프로퍼티는 CrowRx.Json 포함 특성이 지정된 경우에만 포함한다.

기본적으로 포함되는 멤버도 CrowRx.Json 제외 특성으로 제외할 수 있다.

구체적인 특성 이름과 플랫폼 특성과의 상호작용은 구현 전에 정의해야 한다. `System.NonSerializedAttribute` 및 Unity 직렬화 특성 지원은 호환성에 관한 별도 결정이며 암묵적인 요구사항이 아니다.

### 5.3 읽기 전용 멤버

- setter가 없는 읽기 가능한 프로퍼티와 readonly 필드는 생성자 매개변수에 바인딩할 수 있을 때 왕복 직렬화에 참여할 수 있다.
- 생성자에 바인딩되지 않는 읽기 전용 멤버는 기본적으로 제외한다.
- 계산 프로퍼티는 직렬화 전용 출력 대상으로 명시하지 않는 한 기본적으로 제외한다.
- 객체 생성 후 리플렉션으로 readonly 필드를 변경해서는 안 된다.

### 5.4 상속

조건을 만족하는 상속된 public 멤버는 포함한다. 기반 타입에서 선언한 private 멤버는 명시적으로 표시되어 있고 런타임에서 안전하게 접근할 수 있을 때만 포함한다.

상속 계층에서 멤버 이름이 충돌하면 설정 오류로 처리하며 조용히 하나를 선택해서는 안 된다.

### 5.5 멤버 이름

멤버 이름은 기본적으로 대소문자를 구분해 비교한다. 명명 정책과 멤버별 이름 재정의는 명시적인 옵션으로 추가할 수 있다.

두 C# 멤버가 같은 JSON 이름으로 결정되어서는 안 된다.

## 6. 객체 생성

기본 역직렬화기는 접근 가능한 매개변수 없는 생성자 또는 모호하지 않게 선택할 수 있는 매개변수 생성자를 가진 DTO 클래스를 지원한다. 구조체는 기본값으로 초기화하거나 필요한 경우 선택한 생성자를 사용한다.

불변 DTO와 record가 왕복 직렬화에 참여할 수 있도록 생성자 바인딩을 초기 2.x 사양에 포함한다.

생성자 매개변수는 일반적인 camelCase/PascalCase 불변 DTO를 지원하도록 대소문자를 무시해 직렬화 멤버 이름과 연결한다. 실제 JSON 입력 이름 비교는 설정된 member matching 정책을 따른다. 모든 필수 생성자 매개변수에는 호환되는 JSON 값 또는 명시적인 기본값이 있어야 한다.

생성자 선택은 결정적이어야 한다. 초기 구현은 다음 우선순위를 사용한다.

1. JSON 역직렬화용으로 명시된 생성자
2. 접근 가능한 public 생성자가 하나뿐인 경우 해당 생성자
3. 접근 가능한 public 매개변수 없는 생성자

같은 우선순위에 해당하는 생성자가 둘 이상이면 생성자 모호성 오류로 실패한다. 리플렉션이 먼저 반환한 생성자를 임의로 선택해서는 안 된다.

객체를 생성한 후 나머지 쓰기 가능한 멤버를 일반 규칙에 따라 채운다.

다른 생성 규칙이 필요한 타입에는 다음 중 하나가 필요하다.

- 등록된 커스텀 액티베이터
- 등록된 컨버터

## 7. null 처리

- JSON `null`은 참조 타입과 nullable 값 타입에 대응한다.
- JSON `null`을 nullable이 아닌 값 타입에 대입하려 하면 실패한다.
- C#의 `null` 값은 JSON `null`로 직렬화한다.
- 누락된 멤버와 명시적으로 `null`인 멤버는 서로 다른 경우로 취급한다.
- nullable 참조 타입 표기는 진단에 사용할 수 있지만 완전한 런타임 검증 체계로 간주하지 않는다.

## 8. 누락된 멤버와 알 수 없는 멤버

기본 동작은 다음과 같다.

- JSON에서 누락된 멤버는 C# 멤버의 초기값을 유지한다.
- C# 타입에 없는 JSON 멤버는 무시한다.
- JSON에 존재하는 멤버의 값을 변환할 수 없으면 전체 작업이 실패한다.

알 수 없는 멤버를 엄격하게 처리하는 기능은 옵션으로 제공할 수 있다.

## 9. 실패와 원자성

성공한 작업은 JSON에 존재하면서 선택 대상인 모든 멤버가 성공적으로 변환되었음을 보장한다. 필드 단위 실패를 버리고 전체 성공을 반환해서는 안 된다.

실패 정보에는 다음 항목이 포함되어야 한다.

- 오류 범주
- JSON 경로
- 예상한 C# 타입
- 실제 JSON 토큰 타입
- 가능한 경우 원본 위치
- 사람이 이해할 수 있는 설명

예외 기반 API와 `Try` API를 함께 제공할 수 있지만, 두 API의 근본적인 실패 의미는 같아야 한다.

새 객체로 역직렬화하는 작업은 호출자 관점에서 원자적이어야 한다. 일부만 채워진 결과를 성공으로 반환하지 않는다.

## 10. 덮어쓰기와 추가 동작

덮어쓰기는 일반 역직렬화와 구분되는 별도 작업이다.

- DTO 덮어쓰기는 JSON 입력에 존재하는 멤버만 갱신한다.
- 컬렉션 교체는 기존 컬렉션을 비우고 다시 채운다.
- 추가 모드는 명시적으로 지원하는 리스트와 딕셔너리 타입에만 제공한다.
- 딕셔너리 추가 모드에서는 중복 키가 있으면 기본적으로 실패한다.
- 덮어쓰기가 실패했을 때 기존 객체가 일부 변경될 수 있는지 API 문서에 명확히 밝혀야 한다.

목표는 트랜잭션 방식의 덮어쓰기지만, 구현 전략과 성능 예산이 승인되기 전까지 보장하지 않는다.

## 11. 참조 그래프와 재귀

CrowRx.Json은 임의의 참조 그래프가 아니라 JSON 트리를 직렬화한다.

- 참조 동일성을 보존하지 않는다.
- 순환 참조를 발견하면 제어된 직렬화 실패를 반환한다.
- 설정 가능한 최대 깊이로 과도한 재귀를 방지한다.
- 같은 객체를 여러 번 참조하는 경우 순환이 아니라면 각각 별도의 값으로 직렬화한다.

## 12. 사용자 정의

사용자 정의는 타입을 기준으로 명시적으로 설정한다.

- 타입을 읽고 쓰는 커스텀 컨버터
- 타입을 생성하는 커스텀 액티베이터
- 명명 및 검증 정책을 담은 직렬화 옵션

컨버터는 리플렉션 기반 DTO 처리보다 우선한다. 전역 변경 가능 레지스트리는 사용하지 않으며, 설정은 직렬화 옵션 또는 직렬화기 인스턴스에 속한다.

## 13. Unity 경계

코어 패키지는 `UnityEngine`에 의존하지 않는다.

- 일반 C# DTO는 .NET과 Unity에서 동일하게 동작해야 한다.
- `UnityEngine.Object` 및 파생 타입은 코어 리플렉션 직렬화기의 지원 대상이 아니다.
- 벡터 같은 Unity 값 타입은 선택적인 Unity 컨버터 패키지로 지원할 수 있다.
- 리플렉션에 의존하면서 Unity 지원을 표방하는 모든 기능은 IL2CPP 및 관리 코드 스트리핑 호환성을 테스트하고 문서화해야 한다.

## 14. 성능 계약

초기 구현은 모든 플랫폼 직렬화기보다 빠르다고 약속하지 않는다. 대신 불필요한 반복 작업을 피할 것을 보장한다.

- 타입별 리플렉션 메타데이터를 캐시한다.
- 객체마다 직렬화 멤버를 반복 탐색하지 않는다.
- 성능상 중요한 경로에서 가능한 한 불필요한 boxing과 임시 할당을 피한다.
- 파서 및 writer 상태는 전역 변경 가능 상태에 의존하지 않는다.
- 캐시와 직렬화기 인스턴스는 문서에 명시된 동시 사용 방식을 안전하게 지원해야 한다.

성능을 주장하려면 처리량, 메모리 할당, 최초 실행, 캐시 준비 이후 실행, 대표적인 중첩 DTO를 포함한 벤치마크가 필요하다.

## 15. 호환성과 버전 관리

기본 멤버 선택, 명명 방식, 열거형 표현, `null` 처리 또는 실패 정책 변경은 직렬화 계약 변경이다. 이러한 변경에는 메이저 버전 변경 또는 명시적인 호환 모드가 필요하다.

같은 타입과 옵션에 대해서는 출력 순서가 결정적이어야 한다. 하지만 JSON 객체의 멤버 순서에는 의미가 없으므로 소비자가 순서에 의존해서는 안 된다.

## 16. 필수 적합성 테스트

어떤 기능을 지원한다고 판단하려면 다음 테스트를 갖춰야 한다.

- 올바른 JSON 문법과 잘못된 JSON 문법
- 모든 기본 스칼라 타입과 경계값
- 숫자 오버플로와 잘못된 숫자 문법
- `null`, 누락된 멤버, 알 수 없는 멤버
- public 필드와 프로퍼티
- 매개변수 생성자, 불변 DTO 및 record
- 생성자 선택, 기본 매개변수 및 모호성 실패
- 명시적으로 포함한 non-public 멤버
- 상속과 멤버 이름 충돌
- 배열, 리스트, 문자열 키 딕셔너리
- 중첩된 실패 경로
- 순환 참조와 최대 깊이
